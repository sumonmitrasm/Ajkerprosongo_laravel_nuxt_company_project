Post Module: পুরো flow

একটি news post কীভাবে form থেকে database-এ save হয়, reviewer-এর কাছে যায়, cache ব্যবহার করে এবং পরে edit/publish হয়—তার বাস্তব code map।

মূল কথা: Blade শুধু UI দেখায়। JavaScript form data পাঠায়। Route সেই request Controller-এ পাঠায়। Controller validate করে Model দিয়ে database-এ save করে। আর dropdown-এর option দ্রুত দেখানোর জন্য Support class cache ব্যবহার করে।

৩. Route থেকে Controller

GET    /admin/posts              → PostController@index       (All News)
GET    /admin/posts/mine         → PostController@index       (My Posts)
GET    /admin/posts/review-queue → PostController@index       (Review Queue)
POST   /admin/post               → PostController@store       (Create)
GET    /admin/post/{post}        → PostController@show        (Edit data)
PUT    /admin/post/{post}        → PostController@update      (Update)
PATCH  /admin/post/{post}/status → PostController@updateStatus
DELETE /admin/post/{post}        → PostController@destroy

এই mapping আছে routes/web.php-এ। একই index() method route name দেখে বোঝে এটি All News, My Posts নাকি Review Queue।

৪. Create Post কীভাবে save হয়

1
Blade form
Post form-এর id="post-form" আছে। User title, description, category, status, reviewer, image ইত্যাদি দেয়।

posts.js
Submit আটকায়: ev.preventDefault()। Quill editor-এর HTML sanitize করে hidden description field-এ দেয়। তারপর new FormData(this) দিয়ে text + image একসঙ্গে পাঠায়।
3
AJAX request
Create-এর সময় POST /admin/post; edit-এর সময় method override সহ PUT /admin/post/{id} যায়। সফল হলে modal বন্ধ হয় এবং list AJAX দিয়ে refresh হয়।
4
Validation
validatePost() title, description, status, image type/size, category ID, reviewer ID, SEO data ইত্যাদি পরীক্ষা করে। ভুল হলে Laravel 422 JSON error পাঠায়; JS form-এ দেখায়।
5
Database transaction
store() image upload করে, তারপর DB::transaction()-এর ভিতরে post, tag pivot, gallery এবং initial status history save করে। কোনো অংশ ব্যর্থ হলে transaction rollback হয়।

৫. Database structure

posts table

মূল article record: title, slug, description, status, featured image, SEO, publish time, author/reviewer ID, flags।

Soft delete Delete করলে row সঙ্গে সঙ্গে মুছে যায় না; deleted_at ভরে যায়।

Connected tables

  • post_images — gallery images
  • post_tag — post ও tag-এর many-to-many link
  • post_revisions — edit-এর আগের version
  • post_status_histories — draft/review/published পরিবর্তনের audit trail
posts.author_id    → admins.id  (যার নামে byline যাবে)
posts.created_by   → admins.id  (কে record তৈরি করেছে)
posts.updated_by   → admins.id  (সর্বশেষ কে edit করেছে)
posts.reviewed_by  → admins.id  (কে review করার দায়িত্ব দেওয়া হয়েছে)
posts.published_by → admins.id  (কে publish করেছে)

৭. Author ও Reviewer flow

Author / Reporter

author_id-তে save হয়। এটি post-এর byline; current logged-in user default হিসেবে থাকে, তবে permitted user অন্য active staff-এর নামও দিতে পারে।

Reviewer / Send for review to

reviewed_by-তে save হয়। Status review হলে reviewer বাধ্যতামূলক। শুধু selected reviewer সেই item নিজের Review Queue-তে দেখেন।

// Reviewer dropdown query
Admin::where('status', true)
  ->where(type = 'superadmin' OR post module-এর edit_access = true)
  ->orderBy('name')
  ->get();

Review Queue filter: where('reviewed_by', loggedInAdminId)->where('status', 'review')। তাই reviewer A-র কাছে reviewer B-র assigned post যাবে না।

৮. Status workflow

Draft
Review
Scheduled
Published
Archived
  • Draft: কাজ চলছে; reviewer দরকার নেই।
  • Review: reviewed_by অবশ্যই selected হতে হবে; reviewed_at এখনো empty থাকে।
  • Scheduled / Published: assigned reviewer অথবা superadmin publish করতে পারে; তখন reviewed_at, published_at ও published_by update হয়।
  • প্রতিটি status change post_status_histories-এ note ও user ID-সহ save হয়।

৯. Support class ও cache কীভাবে কাজ করে

Post create form খোলার সময় বারবার ৮টি আলাদা database query না চালিয়ে PostFormLookups::get() ব্যবহার হয়।

Cache::remember(
  'admin.post-form-lookups.v1',
  now()->addHours(6),
  fn () => self::payload()
);

Cache miss

প্রথমবার cache না থাকলে payload() database থেকে active section/category/tag/admin/reviewer/location নিয়ে আসে এবং ৬ ঘণ্টার জন্য cache রাখে।

Cache hit

পরের form open-এ database query না করে cache থেকে option আসে, তাই modal দ্রুত open হয়।

Cache clear: User/permission, section, category বা tag পরিবর্তনের পরে সংশ্লিষ্ট controller PostFormLookups::forget() চালায়। তাই নতুন reporter/reviewer সাধারণত সঙ্গে সঙ্গেই দেখা যাবে।

১০. Image ও SEO data

  • Featured image / Meta image / Gallery image: upload() file-কে public/admin/postimages/-এ রাখে।
  • Update: নতুন image থাকলে নতুন file save হয়; database update সফল হওয়ার পর পুরোনো image delete হয়।
  • Failure: transaction fail হলে সদ্য upload করা unused files delete করার চেষ্টা হয়।
  • SEO: meta title, description, keywords, image, robots, canonical URL ও JSON schema posts table-এই থাকে।

১২. দ্রুত সমস্যা সমাধান

  • Reviewer নাম কম দেখায়: user Active কি না এবং Post module-এর Edit Access আছে কি না দেখুন।
  • নতুন user দেখা যাচ্ছে না: User/Permission screen দিয়ে update করুন; সেটি lookup cache clear করে। Direct database change করলে cache clear দরকার হতে পারে।
  • Review status save হচ্ছে না: Reviewer select করা আছে কি না দেখুন; Review হলে field required।
  • Post Review Queue-তে নেই: status অবশ্যই review এবং reviewed_by অবশ্যই logged-in reviewer-এর ID হতে হবে।
  • Image upload fail: JPG/JPEG/PNG/WebP এবং 5 MB-এর মধ্যে আছে কি না দেখুন।
