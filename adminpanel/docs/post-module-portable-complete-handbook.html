8. Models, casts ও relationships

Post model

SoftDeletes trait ব্যবহারে delete query row সরায় না; deleted_at বসায়। Booleans, JSON arrays এবং datetimes cast হওয়ায় controller/Blade raw string নিয়ে কাজ করতে হয় না।

class Post extends Model
{
    use SoftDeletes;

    protected $casts = [
        'scheduled_at' => 'datetime',
        'reviewed_at' => 'datetime',
        'published_at' => 'datetime',
        'is_breaking' => 'boolean',
        'is_featured' => 'boolean',
        'is_pinned' => 'boolean',
        'allow_comments' => 'boolean',
        'featured_positions' => 'array',
        'schema_markup' => 'array',
    ];

    public function images(): HasMany
    {
        return $this->hasMany(PostImage::class)->orderBy('position');
    }

    public function tags(): BelongsToMany
    {
        return $this->belongsToMany(Tag::class)->withTimestamps();
    }
}
MethodRelationMeaning
section(), category()belongsToTaxonomy parent
division(), district(), upazila()belongsToGeographic parents
author(), creator(), updater()belongsTo AdminContent owner ও audit users
reviewer(), publisher()belongsTo AdminWorkflow actors
images(), revisions(), statusHistories()hasManyChild records; history created_at তারপর id order
tags()belongsToManypost_tag pivot

Child models

  • PostImage: fillable metadata, boolean is_featured, belongs to Post.
  • PostRevision: $timestamps = false, created_at datetime cast, belongs to Post/editor.
  • PostStatusHistory: $timestamps = false, created_at datetime cast, belongs to Post এবং changedBy Admin.

Port করার সময়: শুধু model copy করলে হবে না। Related Section/Category/Tag/location/Admin model namespaces এবং database keys একই না হলে relationship method ও foreign keys বদলাতে হবে।

10. Permission ও record-level authorization

নিরাপত্তা দুই স্তরের: middleware বলে “এই feature ব্যবহার করতে পারবে কি না”, controller বলে “এই নির্দিষ্ট post-এ action করতে পারবে কি না”। UI button লুকানো তৃতীয় সুবিধামূলক স্তর—এটি security boundary নয়।

11. List, scope, filter, eager loading ও pagination

Route name থেকে list scope

posts.mine

created_by = current admin অথবা author_id = current admin।

posts.review

reviewed_by = current admin এবং status = review। Edit permission-ও লাগে।

posts

Superadmin সব দেখে; অন্য admin নিরাপত্তার জন্য mine scope-এ সীমাবদ্ধ।

Query optimization

$posts = $visibleQuery()
    ->select([
        'id', 'title', 'status', 'category_id', 'author_id',
        'featured_image', 'is_breaking', 'is_featured',
        'scheduled_at', 'published_at', 'created_at',
    ])
    ->with(['category:id,name', 'author:id,name'])
    ->when($request->search, fn ($q, $search) =>
        $q->where('title', 'like', "%{$search}%"))
    ->when($request->status, fn ($q, $status) =>
        $q->where('status', $status))
    ->latest()
    ->paginate(10)
    ->withQueryString();
  • select() list-এ অপ্রয়োজনীয় long description/SEO JSON আনে না।
  • with() category/author-এর N+1 query আটকায়। Loop-এর ভিতরে প্রতিটি post-এর জন্য নতুন query হয় না।
  • paginate(10) সব row memory-তে তোলে না এবং filters পরের page link-এ থাকে।
  • Dashboard cards চার query না চালিয়ে একটি conditional aggregate query-তে total/published/draft-review/scheduled count নেয়।

Search scale note: LIKE %keyword% B-tree index পুরোপুরি ব্যবহার করতে পারে না। লক্ষ/কোটি article ও complex Bengali search-এর জন্য Meilisearch/OpenSearch/Elasticsearch বা Laravel Scout বিবেচনা করুন।

12. Create flow: store()

validatePost()
→
upload featured/meta/gallery
→
DB transaction
→
Post::create
→
tags + gallery + history
  1. Shared validation সব scalar, FK, file, array এবং conditional field পরীক্ষা করে।
  2. নতুন featured/meta/gallery files public directory-তে upload হয়; paths একটি cleanup list-এ রাখা হয়।
  3. Transaction-এর মধ্যে normalized postData() দিয়ে Post তৈরি হয়।
  4. $post->tags()->sync($tagIds) pivot rows exact selection অনুযায়ী বসায়।
  5. saveGallery() image rows positionসহ রাখে।
  6. Initial status history: from_status = null, to_status = selected status, note “Post created.”
  7. Success-এ HTTP 201 JSON; exception হলে DB rollback এবং নতুন uploaded files cleanup।
DB::transaction(function () use ($data, $request, $paths) {
    $post = Post::create($this->postData($data, $request, $paths));
    $post->tags()->sync($data['tag_ids'] ?? []);
    $this->saveGallery($post, $request, $paths['gallery'] ?? []);

    $post->statusHistories()->create([
        'changed_by' => Auth::guard('admin')->id(),
        'from_status' => null,
        'to_status' => $post->status,
        'note' => 'Post created.',
        'created_at' => now(),
    ]);
});

কেন upload transaction-এর আগে? UploadedFile move database query নয়, তাই DB transaction file rollback করতে পারে না। Code explicit cleanup list ব্যবহার করে failure compensate করে। Object storage ব্যবহার করলে একই compensating cleanup pattern রাখতে হবে।

update(): old snapshot আগে, mutation পরে

  1. Edit ও requested status authorization.
  2. Shared validation এবং optional replacement files upload.
  3. Transaction শুরু; saveRevision() update-এর আগের content snapshot রাখে।

15. Delete behavior

destroy() delete authorization-এর পরে deleted_by update করে এবং SoftDeletes দিয়ে row soft-delete করে। Featured/gallery files ইচ্ছাকৃতভাবে রাখা হয়, যাতে restore সম্ভব হলে content broken না হয়।

$post->update(['deleted_by' => Auth::guard('admin')->id()]);
$post->delete(); // deleted_at set; row/file স্থায়ীভাবে মুছে যায় না

সুবিধা

Accidental deletion recoverable; audit actor থাকে; child rows ও media অক্ষত।

private function uniqueSlug(?string $requested, string $title, ?int $ignoreId = null): string
{
    $base = Str::slug($requested ?: $title) ?: 'post';
    $slug = $base;
    $suffix = 2;

    while (Post::where('slug', $slug)
        ->when($ignoreId, fn ($q) => $q->whereKeyNot($ignoreId))
        ->exists()) {
        $slug = $base.'-'.$suffix++;
    }
    return $slug;
}

অর্থাৎ “My News” আগে থাকলে নতুনটি my-news-2, এরপর my-news-3। Database unique index concurrency-এর শেষ protection; খুব উচ্চ concurrent create হলে duplicate-key exception retry strategy যোগ করা যায়।

final class PostFormLookups
{
    private const CACHE_KEY = 'admin.post-form-lookups.v1';

    public static function get(): array
    {
        return Cache::remember(
            self::CACHE_KEY,
            now()->addHours(6),
            fn () => self::queryDatabase()
        );
    }

    public static function forget(): void
    {
        Cache::forget(self::CACHE_KEY);
    }
}

function optionFilter($select, key, value, keepValue = null) {
    $select.find('option').each(function () {
        const $option = $(this);
        const visible = !$option.val() || String($option.data(key)) === String(value);
        $option.prop('disabled', !visible).prop('hidden', !visible);
    });

    if (keepValue !== null) $select.val(String(keepValue));
}

Portable module-এর recommended service boundary

Admin UI / API
    ├─ PostQueryService       (list/filter/read projections)
    ├─ PostCommandService     (create/update/delete transaction)
    ├─ EditorialService       (status rules + history)
    ├─ PostMediaService       (upload/delete/variants)
    └─ PostFormLookups        (cached form reference data)

Domain events
    ├─ PostPublished  ─> invalidate public cache / notify / index search
    ├─ PostUpdated    ─> refresh detail/search index
    └─ PostArchived   ─> remove from feeds/search/cache

বর্তমান controller compact project-এর জন্য workable এবং query/cache optimizations আছে। Module বড় হলে উপরের service boundaries ধাপে ধাপে extract করবেন—একবারে rewrite নয়। Feature tests আগে থাকলে extraction behavior-safe হয়।

শেষ কথা: অন্য project-এ সফল reuse-এর মূল হলো file copy নয়—schema, identity, permission, storage, response contract ও workflow rules একসঙ্গে map করা। এই document সেই map হিসেবে ব্যবহার করুন।
