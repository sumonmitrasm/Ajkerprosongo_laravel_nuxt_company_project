১. কেন PostFormLookups তৈরি হয়েছে?

Post Add/Edit form খুলতে একই ধরনের lookup data বারবার লাগে: Section, Category, Tag, Author/Admin, Reviewer এবং বাংলাদেশের Location data। আগে প্রতিটি Post list request-এ এগুলোর জন্য আলাদা database query চলত।

Cache-এর আগেCache warm হওয়ার পরে
প্রতি request-এ একাধিক lookup table queryএকটি cache read
একই data বারবার sort ও serializeআগে প্রস্তুত করা payload reuse
Database connection বেশি ব্যস্তDatabase cache-এ ১ query; Redis-এ DB query শূন্য
Scope: এটি Post/News record cache করে না। শুধু Post form-এর dropdown/options cache করে। তাই নতুন news প্রকাশ আটকে যায় না।

২. সম্পূর্ণ Request Flow

Post page request→PostController::index()→PostFormLookups::get()→Cache check→Blade view

Cache hit

Key পাওয়া গেছে→Cached array→Object collection→Form render

Cache miss

Key নেই/expired→payload() queries→Cache save→Form render

৩. Service File এবং প্রতিটি অংশ

File: app/Support/PostFormLookups.php

app/Support হলো reusable application service রাখার জায়গা। এটি Model নয়, Controller নয় এবং database table-ও নয়। এটি কয়েকটি Model query ও Laravel Cache facade-কে একটি reusable API-তে আনে।

Namespace ও imports

<?php

namespace App\Support;

use App\Models\{Admin, Category, District, Division, Section, Tag, Upazila};
use Illuminate\Support\Facades\Cache;
use Throwable;
Importকাজ
App\Models\...Lookup table থেকে data query করে।
CacheConfigured cache driver—database বা Redis—ব্যবহার করে।
ThrowableCache server/driver ব্যর্থ হলেও fallback চালাতে সাহায্য করে।

একটি versioned cache key

private const CACHE_KEY = 'admin.post-form-lookups.v1';

v1 রাখার সুবিধা হলো payload structure ভবিষ্যতে বদলালে key-কে v2 করে পুরোনো cache নিরাপদে বাদ দেওয়া যায়।

get(): cache read/create

public static function get(): array
{
    try {
        $payload = Cache::remember(
            self::CACHE_KEY,
            now()->addHours(6),
            fn () => self::payload(),
        );
    } catch (Throwable $exception) {
        report($exception);
        $payload = self::payload();
    }

    return collect($payload)->map(
        fn (array $records) => collect($records)
            ->map(fn (array $record) => (object) $record),
    )->all();
}
  1. Cache::remember() প্রথমে key খোঁজে।
  2. Key থাকলে database query না করে cached payload দেয়।
  3. Key না থাকলে payload() চালায় এবং result ছয় ঘণ্টার জন্য save করে।
  4. Cache connection error হলে exception log হয়, তারপর সরাসরি payload() চালিয়ে page সচল রাখে।
  5. Cached array-কে object collection করা হয়, কারণ Blade-এ existing code $item->id ও $item->name ব্যবহার করে।
কেন array cache করা হয়? Eloquent Model serialize না করে plain array রাখলে cache driver পরিবর্তন, model serialization এবং security compatibility সহজ হয়।

forget(): targeted invalidation

public static function forget(): void
{
    try {
        Cache::forget(self::CACHE_KEY);
    } catch (Throwable $exception) {
        report($exception);
    }
}

পুরো application cache clear করা হয় না। শুধু admin.post-form-lookups.v1 key মুছে যায়। পরবর্তী Post page request fresh payload তৈরি করে।

৪. payload() কোন data query করে?

private static function payload(): array
{
    return [
        'sections' => Section::where('status', true)
            ->orderBy('name')->get(['id', 'name'])->toArray(),

        'categories' => Category::where('status', true)
            ->orderBy('category_name')
            ->get(['id', 'section_id', 'category_name'])->toArray(),

        'tags' => Tag::where('status', true)
            ->orderBy('name')->get(['id', 'name'])->toArray(),

        'admins' => Admin::where('status', true)
            ->orderBy('name')
            ->get(['id', 'name', 'type', 'rank', 'position'])->toArray(),

        'reviewers' => Admin::where('status', true)
            ->where(fn ($query) => $query->where('type', 'superadmin')
                ->orWhereHas('roles', fn ($role) => $role
                    ->where('module', 'post')
                    ->where('edit_access', true)
                    ->where('no_access', false)))
            ->orderBy('name')
            ->get(['id', 'name', 'type', 'rank', 'position'])->toArray(),

        'divisions' => Division::orderBy('name')
            ->get(['id', 'name', 'bn_name'])->toArray(),
        'districts' => District::orderBy('name')
            ->get(['id', 'division_id', 'name', 'bn_name'])->toArray(),
        'upazilas' => Upazila::orderBy('name')
            ->get(['id', 'district_id', 'name', 'bn_name'])->toArray(),
    ];
}

প্রতিটি query-তে প্রয়োজনীয় column-ই select করা হয়েছে। division_id ও district_id cascading location dropdown filter করার জন্য রাখা হয়েছে।

৫. কোথায় কী Import করতে হবে?

যে Controller PostFormLookups::get() বা ::forget() call করবে, তার namespace-এর নিচে এই import দিতে হবে:

use App\Support\PostFormLookups;
Fileকেন importCall
PostController.phpForm options পড়তেPostFormLookups::get()
SectionController.phpSection বদলালে stale cache সরাতেPostFormLookups::forget()
CategoryController.phpCategory বদলালে stale cache সরাতেPostFormLookups::forget()
TagController.phpTag বদলালে stale cache সরাতেPostFormLookups::forget()
AdminController.phpAuthor/reviewer/permission বদলালে cache সরাতেPostFormLookups::forget()
একই namespace-এ না থাকলে শুধু class name লিখে call করা যাবে না। Import না দিলে PHP App\Http\Controllers\PostFormLookups খুঁজবে এবং “Class not found” error দেবে।

৭. Cache Invalidation: data বদলালে সঙ্গে সঙ্গে fresh

Cache-এর সবচেয়ে গুরুত্বপূর্ণ নিয়ম: source data বদলালে সংশ্লিষ্ট key forget করতে হবে। তা না হলে TTL শেষ হওয়া পর্যন্ত পুরোনো option দেখা যাবে।

SectionController

use App\Support\PostFormLookups;

private function clearSectionCache(): void
{
    Cache::forget('api.sections-with-categories.v1');
    PostFormLookups::forget();
}

CategoryController

use App\Support\PostFormLookups;

private function clearCategoryCache(): void
{
    Cache::forget('api.sections-with-categories.v1');
    Cache::forget('admin.category-form.sections.v3');
    Cache::forget('admin.category-form.parents.v3');
    PostFormLookups::forget();
}

TagController

use App\Support\PostFormLookups;

public function store(Request $request)
{
    Tag::create($this->validatedData($request));
    PostFormLookups::forget();

    return response()->json(['message' => 'Tag created successfully.'], 201);
}

একই forget() Tag-এর update, updateStatus ও destroy-এর successful database change-এর পরে call করতে হবে।

৮. Cache Lifecycle: ছয় ঘণ্টা মানে কী?

ঘটনাকী হয়?
প্রথম Post page requestCache miss → source queries → payload save → response।
পরবর্তী requestএকই key cache থেকে read; source lookup queries চলে না।
৬ ঘণ্টা পার হয়Key expired; পরবর্তী request নতুন payload তৈরি করে। Expire নিজে error নয়।
Tag/Category/Admin পরিবর্তনforget() সঙ্গে সঙ্গে key সরায়; পরবর্তী request fresh data পায়।
Cache server সাময়িক downException report হয়; service source database queries দিয়ে response দেয়।
সরাসরি DB editController invalidation চলে না; key expire/ম্যানুয়াল forget না হওয়া পর্যন্ত পুরোনো option থাকতে পারে।

সময় পরিবর্তন

// 30 minutes
now()->addMinutes(30)

// 6 hours (বর্তমান)
now()->addHours(6)

// 1 day
now()->addDay()

Invalidation ঠিক থাকলে দীর্ঘ TTL নিরাপদ এবং বেশি কার্যকর। Location data খুব কম বদলায়; Tag/Admin পরিবর্তনে explicit invalidation আছে।

৯. নতুন News যোগ করলে frontend-এ কী হবে?

PostFormLookups শুধু form options cache করে। এটি posts table-এর news list, post body বা published API response cache করে না।

Post save→posts table insert/update→Admin list refresh→নতুন Post দেখা যায়
Dataএই service cache করে?Fresh হওয়ার নিয়ম
Post/news recordনাপরবর্তী database-backed list request-এ fresh
Post title/description/statusনাSave হওয়ার সঙ্গে DB-তে fresh
Section/Category/Tag optionsহ্যাঁRelated CRUD-এর forget()
Public Nuxt/API responseনাসেই API/CDN cache policy আলাদা
Published frontend cache আলাদা বিষয়: ভবিষ্যতে homepage, category page বা single-news API cache করলে Post publish/update/delete-এর পরে সেই public cache keys আলাদাভাবে invalidate করতে হবে। PostFormLookups::forget() public news cache clear করে না।

১০. বর্তমান Performance Result

Local MySQL এবং বর্তমান database cache driver-এ মাপা ফল:

১১. Database Cache থেকে Redis

PostFormLookups কোনো নির্দিষ্ট driver hard-code করে না। Laravel-এর Cache facade default driver ব্যবহার করে। তাই application code না বদলিয়েই environment দিয়ে driver বদলানো যায়।

১৪. সংক্ষিপ্ত FAQ

Cache expire হলে কি error হবে?

না। পরবর্তী request payload() চালিয়ে নতুন cache তৈরি করবে।

নতুন Post save করলে lookup cache clear করতে হবে?

না। Post record এই cache-এর অংশ নয়।

নতুন Category/Tag save করলে?

হ্যাঁ—সংশ্লিষ্ট Controller ইতিমধ্যে forget() call করে।

Database cache table রাখা যাবে?

হ্যাঁ। Redis driver চালু হলেও database cache table থাকা ক্ষতিকর নয় এবং rollback সহজ করে।

Redis-এ গেলে service code বদলাতে হবে?

না। শুধু Redis server/client এবং .env driver configure করতে হবে।

Cache down হলেও Post page কেন চলে?

get()-এর catch block source database থেকে payload আনে। তবে application-এর অন্য cache-dependent feature-এর জন্য healthy cache service জরুরি।

১৫. Implementation Checklist

  • app/Support/PostFormLookups.php namespace ঠিক আছে।
  • PostController-এ import ও ...PostFormLookups::get() আছে।
  • Section/Category/Tag/Admin mutation-এর পরে targeted forget() আছে।
  • Reviewer permission update-এর পরেও invalidation আছে।
  • Cache payload plain array; return value Blade-compatible object collections।
  • TTL ছয় ঘণ্টা; expiry automatic rebuild করে।
  • News record/public API cache এই service থেকে আলাদা।
  • Redis switch-এর আগে server ping ও client test সফল।
  • Production-এ APP_DEBUG=false এবং monitored Redis ব্যবহার করা হবে।
