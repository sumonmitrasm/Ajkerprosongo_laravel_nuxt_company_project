Admin Cache & Pagination: A to Z

এই project-এ cache, Controller, layout JavaScript এবং AJAX pagination কীভাবে যুক্ত হয়েছে

১. আগে সমস্যা কী ছিল?

সব user একসঙ্গে get() করে Redis-এ Eloquent Collection হিসেবে রাখলে Redis বন্ধ হলে login slow/fail, অনেক data হলে browser slow, এবং object deserialize না হলে __PHP_Incomplete_Class বা Blade type error হতে পারে।

সব record load→বড় payload→slow page→cache type risk

৩. Controller.php কেন লাগল?

সব controller Laravel-এর এই base Controller extend করে। তাই cache-pagination code Users, Sections, Categories, Settings-এ আলাদা করে copy করার দরকার হয় না। এটি কোনো route নয়; এটি common protected method রাখে।

cachedPage(Request $request, string $prefix, Closure $query, Closure $map)

$prefix cache namespace, $query database query, $map model থেকে Redis/database-safe plain array তৈরি করে। Eloquent model cache করা হয় না।

৪. cachedPage() কীভাবে চলে?

users?page=3→page=3→version read→cache key→valid payload?→hit অথবা DB query

Key pattern: admin.users.index.{version}.page.3। Payload-এ items array ও total count থাকে। Payload invalid হলে forget করে database থেকে 25 row নিয়ে আবার cache করে। TTL 6 ঘণ্টা।

৫. AdminController কী করে?

users() method $this->cachedPage($request, 'admin.users.index', fn () => Admin::latest(), ...) call করে। Base controller ভিতরে paginate(25) চালায়। তাই 1,25,000 user থাকলেও একটি page-এ শুধু 25 row আসে। $user->only(...) কেবল প্রয়োজনীয় field array হিসেবে রাখে; password বা Eloquent object cache হয় না।

৬. Data edit হলে cache কীভাবে fresh হয়?

Add, edit, delete ও status update-এর শেষে clearUserCache() চলে। এটি invalidateCachedPages('admin.users.index') call করে। Method একটি নতুন UUID version save করে। ফলে পুরোনো page keys খুঁজে delete করার দরকার নেই; পরের request নতুন version key ব্যবহার করে fresh cache তৈরি করে। পুরোনো keys TTL শেষে শেষ হয়।

৭. Users Blade view

Users table-এ data-server-pagination আছে। নিচে $users->links() pagination HTML দেয়। Items plain array হওয়ায় $user['name'] syntax ব্যবহার হয়েছে। Optional field-এ ?? '-' থাকায় field missing হলেও warning হবে না।

৯. Database cache না Redis?

CACHE_STORE=database
বর্তমানে database cache safe default। Redis process বন্ধ থাকলেও login ও page-load Redis timeout-এর জন্য আটকে থাকবে না। Server-এ php artisan migrate --force চালালে Laravel cache table তৈরি/নিশ্চিত হবে।

Redis reliable service হিসেবে চালু থাকলে CACHE_STORE=redis করা যায়। তার আগে redis-cli ping থেকে PONG নিশ্চিত করুন। Redis off থাকলে redis set করবেন না।

১০. কোন module এখন paginated?

Admin Users, Sections, Categories এবং Settings—চারটি list-এই এখন server-side pagination ও page-wise cache যুক্ত হয়েছে। চারটিই একই cachedPage() method ব্যবহার করে; শুধু query, cache prefix এবং displayed fields আলাদা।
Category create/edit modal-এর parent-category dropdown এখনও সব parent/subcategory cache করে। Data খুব বড় হলে সেই dropdown-এর জন্য আলাদা AJAX search endpoint যোগ করতে হবে। এটি list pagination থেকে আলাদা সমস্যা।

১১. Error আসবে কি?

এই code আগের cache type/serialization error ও Users huge-list loading ঠেকায়। কিন্তু database down, disk full, network failure, wrong credential-এর মতো infrastructure error কোনো application 100% বাদ দিতে পারে না। Production-এ backup, logging, database indexes এবং monitoring দরকার।

১২. Deploy checklist

  1. Server database credentials দিয়ে .env update করুন।
  2. php artisan migrate --force চালান।
  3. php artisan config:clear চালান।
  4. php artisan config:cache চালান।
  5. Redis use করলে আগে redis-cli ping থেকে PONG নিশ্চিত করুন।
  6. Users add/edit/status/delete ও pagination test করুন।
