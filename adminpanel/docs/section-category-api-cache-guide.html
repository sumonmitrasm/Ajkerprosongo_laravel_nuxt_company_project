Section → Category API এবং Cache কীভাবে কাজ করছে

এই document-এ admin panel থেকে তৈরি Section ও Category কীভাবে Nuxt frontend-এ যাবে এবং cache কেন ব্যবহার করা হয়েছে তার সহজ ব্যাখ্যা আছে।

১. API address

GET http://127.0.0.1:8000/api/sections

এই API শুধু Active section, category এবং subcategory পাঠায়।

২. Data flow

Admin Panel → MySQL Database → Laravel API Cache → /api/sections → Nuxt Frontend
  1. Admin থেকে Section তৈরি করবেন।
  2. Category তৈরি করার সময় সেই Section select করবেন।
  3. Nuxt /api/sections call করবে।
  4. প্রথমে section loop হবে; তারপর ওই section-এর ভিতরের category loop হবে।

৩. API response দেখতে কেমন

{
  "data": [

৪. কোন file কী কাজ করছে

Fileকাজ
routes/api.php/api/sections route তৈরি করেছে।
Api/FrontController.phpDatabase থেকে nested section/category data নেয়, API JSON বানায় এবং cache করে।
Models/Section.phpcategories() relation দিয়ে ওই section-এর root category আনে।
Models/Category.phpsubcategories() relation দিয়ে একটি category-এর child category আনে।
SectionController.phpSection change হলে API cache clear করে।
CategoryController.phpCategory change হলে API cache clear করে।

৫. Cache code-এর কাজ

Cache::remember('api.sections-with-categories.v1', now()->addHours(6), function () {
    return $this->sectionPayload();
});
  • api.sections-with-categories.v1 হলো cache-এর unique নাম।
  • প্রথম API call-এ database query হবে ও result cache-এ জমা হবে।
  • পরের call-গুলো ৬ ঘণ্টা পর্যন্ত database query ছাড়া cache থেকে result পাবে।
  • Section অথবা Category create/update/delete/status change হলেই এই cache remove হয়। পরবর্তী call-এ নতুন data আবার cache হবে।
Cache::forget('api.sections-with-categories.v1');
Safety: Cache service কাজ না করলেও API বন্ধ হবে না। Laravel live database থেকে data এনে response দেবে; cache error visitor-এর সামনে দেখাবে না।

৬. Nuxt-এ section প্রথমে, category ভিতরে

<script setup>
const { data: response } = await useFetch('http://127.0.0.1:8000/api/sections')
const sections = computed(() => response.value?.data ?? [])
</script>

<template>
  <section v-for="section in sections" :key="section.id">
    <h2>{{ section.name }}</h2>

    <NuxtLink
      v-for="category in section.categories"
      :key="category.id"
      :to="`/${category.url}`"
    >
      {{ category.name }}
    </NuxtLink>
  </section>
</template>

৭. বড় production site-এর জন্য

বর্তমানে database cache কাজ করবে। বেশি traffic হলে server-এ Redis চালু করে .env-এ নিচের সেটিং দিন:

CACHE_STORE=redis
REDIS_HOST=127.0.0.1
REDIS_PORT=6379

Redis চালু না থাকলে এই setting দেবেন না; CACHE_STORE=database রাখবেন।

Browser-এ এই address খুলুন:

http://127.0.0.1:8000/api/sections

JSON data এলে API ঠিক আছে। Empty data: [] এলে কোনো active section/category নেই অথবা সম্পর্কযুক্ত data নেই।

৯. সম্পূর্ণ কাজের ধারাবাহিকতা — একটির পর একটি

নিচের ক্রমে codeগুলো কাজ করে। কোনো অংশ পরিবর্তন করলে তার নিচের অংশে কী প্রভাব পড়বে, সেটাও লেখা আছে।

Step 1 — API route তৈরি

File: routes/api.php

use Illuminate\Support\Facades\Route;
use App\Http\Controllers\Api\FrontController;

Route::get('/sections', [FrontController::class, 'sections'])
    ->name('api.sections');

এর ফলে browser/Postman/Nuxt থেকে GET /api/sections করলে FrontController-এর sections() method চলবে।

Step 2 — Section-এর সাথে Category relation

File: app/Models/Section.php

public function categories(): HasMany
{
    return $this->hasMany(Category::class)
        ->where('parent_id', 0)
        ->where('status', true)
        ->orderBy('position')
        ->orderBy('category_name');
}

hasMany(Category::class) মানে: একটি section-এর অনেক category থাকতে পারে। parent_id = 0 শুধু root/main category নেয়। শুধু active category নেওয়ার জন্য status = true ব্যবহার হয়েছে।

Step 3 — Category-এর সাথে Subcategory relation

File: app/Models/Category.php

public function subcategories(): HasMany
{
    return $this->hasMany(Category::class, 'parent_id')
        ->where('status', 1)
        ->orderBy('position')
        ->orderBy('category_name');
}

এখানে একই categories table ব্যবহার হয়েছে। Child category-এর parent_id তার parent category-এর ID-এর সমান হয়।

Step 4 — Database থেকে একবারে nested data নেওয়া

File: app/Http/Controllers/Api/FrontController.php

Section::query()
    ->select('id', 'name')
    ->where('status', true)
    ->with([
        'categories:id,section_id,parent_id,category_name,url,image,position',
        'categories.subcategories:id,section_id,parent_id,category_name,url,image,position',
    ])
    ->orderBy('name')
    ->get();

with() খুব গুরুত্বপূর্ণ। এটি eager loading করে; অর্থাৎ section, category ও subcategory আলাদা আলাদা অসংখ্য query-তে না এনে অল্প query-তে একবারে আনে। বড় portal-এর জন্য এটি প্রয়োজনীয়।

Step 5 — API JSON response সাজানো

->map(fn (Section $section) => [
    'id' => $section->id,
    'name' => $section->name,
    'categories' => $section->categories->map(fn ($category) => [
        'id' => $category->id,
        'name' => $category->category_name,
        'url' => $category->url,
        'subcategories' => $category->subcategories->map(...)->values()->all(),
    ])->values()->all(),
])->values()->all();

এখানে admin table-এর অপ্রয়োজনীয় SEO field পাঠানো হচ্ছে না। Nuxt-এর জন্য দরকারি id, name, url, image এবং subcategories পাঠানো হচ্ছে।

Step 6 — Cache-এ result রাখা

try {
    $sections = Cache::remember(
        'api.sections-with-categories.v1',
        now()->addHours(6),
        fn () => $this->sectionPayload(),
    );
} catch (Throwable $exception) {
    report($exception);
    $sections = $this->sectionPayload();
}

প্রথম API request database থেকে data এনে ৬ ঘণ্টার জন্য cache করে। পরের request দ্রুত cache থেকে data পায়। Cache server/database-এ সমস্যা হলে catch অংশ database থেকে live data পাঠায়, তাই public API 500 error দেয় না।

Step 7 — Browser/CDN cache header

return response()
    ->json(['data' => $sections])
    ->header('Cache-Control', 'public, max-age=300, stale-while-revalidate=60');

Browser/CDN ৫ মিনিট API result রাখতে পারবে। এতে একই visitor বারবার page খুললেও server request কম হয়।

Step 8 — Admin থেকে data change হলে cache clear

File: SectionController.php এবং CategoryController.php

private function clearSectionCache(): void
{
    Cache::forget('api.sections-with-categories.v1');
}

private function clearCategoryCache(): void
{
    Cache::forget('api.sections-with-categories.v1');
}

Section/Category add, update, delete অথবা status change method-এর শেষে এই function call হয়। তাই admin থেকে পরিবর্তনের পর পুরনো API data থাকবে না।

Step 9 — আজকের API error কেন হয়েছিল এবং কীভাবে ঠিক হয়েছে

আগের error: _PHP_Incomplete_Class_Name: Illuminate\Support\Collection

Database cache Laravel Collection object সঠিকভাবে restore করতে পারেনি। তাই cache-এ object না রেখে plain PHP array পাঠানো হয়েছে।

// ভুল: এটি Collection return করে
->values()

// ঠিক: এটি plain array return করে এবং cache-safe
->values()->all()

তারপর পুরনো faulty cache key remove করা হয়েছে:

php artisan cache:forget api.sections-with-categories.v1
php artisan optimize:clear
পরীক্ষা করা হয়েছে: http://127.0.0.1:8000/api/sections থেকে 200 OK এবং section → category → subcategory JSON response পাওয়া গেছে।
